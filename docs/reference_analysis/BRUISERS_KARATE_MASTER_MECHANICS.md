# Bruisers / Karate Master 2 机制拆解与 MAWS 转化

## 审计边界

- 本文只记录本机已安装版本中可非破坏读取的文件结构、明文配置、短机制标识和发行包元数据。
- 没有绕过 DRM，没有导出第三方美术、音频、完整文本或完整代码，也不把第三方资源写入 MAWS。
- 结论分为“可确认”“中等证据”“设计推导”。推导不是对原作实现的事实声明。

## Bruisers Steam Demo 0.1

### 技术证据

- 发行包包含 GameMaker `data.win`，文件头与 Windows Runner 元数据均指向 GameMaker Studio 2。
- 外置内容以音频、控制器映射和少量配置为主；核心逻辑位于发行容器中。
- 本次只读取资源名、短机制标识和内嵌帮助文本，没有导出脚本或资源。

### 可确认机制

1. 战斗输入覆盖直拳、摆拳、上勾、重拳、格挡、下潜、推开、缠抱和四向闪避。
2. 战斗统计区分出拳、命中、反击、重击、身体击打、受伤、倒地与 KO。
3. AI 至少区分持续抱架、后撤、防守移动、进攻移动、极端防守和站桩等行为倾向。
4. 生涯准备包含体能训练、跳绳、速度球、跑台、饮食、体重、财务、装备、伤势和药检压力。
5. 核心循环是“赛前准备影响比赛夜”，而不是训练页和战斗页互不相干。
6. 顶层 UI 只显示年份、体重/目标、体力、等级、现金和比赛收益；详细系统进入独立页面。

### 中等证据

- 对手由“风格、拳商、当前状态”共同决定行为，但具体 AI 权重不可确认。
- 身体击打、过度移动和低体力会改变回合策略，但具体公式不可确认。
- 剧情压力会通过财务、名声、规则和比赛选择进入生涯循环。

## Karate Master 2 Knock Down Blow

### 技术证据

- 发行目录主要由两个 32 位 PE 与 Clickteam 扩展组成。
- PE overlay 与 Clickteam 元数据表明内容使用 Fusion/MMF 系运行壳封装。
- 没有可直接读取的 JSON、Lua、CSV 或独立明文机制表；本次不解密、不反编译封装数据。

### 可确认范围

- 文件短标识可确认段位/级位、道场、工作、休息、饮食、疼痛、格挡和反击等概念存在。
- 标准音频流位于大数据 overlay 中，但未导出、未播放。

### 设计推导

1. 训练、工作、休息、饮食和比赛应互相争夺时间，而不是全部都能刷满。
2. 训练带来疲劳和疼痛，恢复和饮食决定玩家能否把训练成果带进实战。
3. 段位或章节目标提供长期方向，单次训练只解决眼前短板。
4. 失败应指出距离、格挡、反击或恢复问题，并把建议送回下一天。

## 对 MAWS 的共同启示

| 参考原则 | MAWS 转化 | 不采用 |
| --- | --- | --- |
| 准备影响比赛 | `combatPrep` 将热饭、冷敷等一次性准备带进下一场战斗 | 不复制任何原作数值或菜单结构 |
| 状态决定打法 | 体力、架势、疲劳和轻伤改变计划建议与复盘 | 不把日常做成复杂体重模拟器 |
| 对手有风格 | 保留 MAWS 的敌人标签、读招、战术配方和 objective 胜利 | 不复制对手、赛事或 AI 代码 |
| 训练有代价 | 30/60/90/120 分钟投入继续承担疲劳、伤病和机会成本 | 不把硬练变成稳定最优解 |
| 消费有功能 | 食材、自制餐饮、冰袋、绷带、外用药分别服务补给、恢复和下一战 | 不做无限叠加药水或付费胜利 |
| 失败回流 | 战斗窗口短评、复盘和下一地点建议进入次日 Director | 不用单纯失败弹窗结束体验 |

## MAWS 第一批实现决策

### 自制餐饮

- 便利店出售鸡蛋、青菜和挂面。
- 出租屋每天可用 30 分钟做一次鸡蛋青菜面。
- 做饭消耗真实库存，产出一份成品，不直接永久加属性。
- 吃下成品会恢复少量日常状态，并写入一次性的“热饭打底”。
- 下一场战斗开始时增加战斗体力和士气，随后立即消耗；睡过当天会失效。

### 恢复用品

- 一次性冰袋降低轻度疲劳并写入“关节冷敷”，下一场增加少量架势准备。
- 弹性绷带继续处理轻伤回合数。
- 外用止痛凝胶只缓解轻伤和健康，不会清空严重伤病，也不能替代理疗。

### 日常降噪

- 主界面仍只突出今日主线、当前地点和最多 2-3 个推荐行动。
- 做饭、整理补给、轻恢复属于“备战准备”，不成为新的独立主循环。
- 同类准备每日有限制，准备只服务下一场战斗或当天剧情选择。
- 后续将低价值微行动收进一个折叠层，不与主线、训练和战斗争夺第一视觉层级。

### 战斗动画

- 主角战斗表扩展为 24 帧：待机、攻击、受击、旧防御段、独立抱架、独立后撤。
- `guard`、`retreat/dodge/escape` 使用不同动作范围，不再统一播放一次泛用 VFX 动作。
- 角色保持底部中心锚点和等比缩放；最终精灵表校验同一动作段的脚底基线与 500KB 预算。

## 后续实现顺序

1. 让备战准备出现在今日建议与战斗开场短报中。
2. 给 E01/E10 增加独立格挡/后撤帧，统一敌我动作语义。
3. 将训练、商店、NPC、事件选项、Toast 和城市 tooltip 全部纳入位图 UI 截图门。
4. 把低价值日常动作合并为“整理/放空/联系”三个微行动组。
5. 基于 Day 1-9 人工试玩数据调食材价格、准备收益和伤病恢复，不凭参考游戏猜公式。
